## 011 — Entity / Ownership Resolution X-Ray — REFRAME / KEEP
**Public question:** Are these records really talking about the same person, company, product, policy, owner, or source?
**Primary user:** researcher, founder, lawyer, journalist, operator, consumer trying to reconcile conflicting records.
**Novice path:** paste/upload a few names or records → system groups likely matches → shows why → user confirms/overrides.
**Expert depth:** configurable match thresholds, entity types, relationship evidence, source authority, temporal identity, beneficial-ownership edges, ambiguous/contested matches.
**A technological ceiling:** hybrid entity resolution using deterministic rules + embeddings + graph-based relational evidence + temporal constraints + provenance + confidence calibration + human adjudication queue. For organization/ownership cases, support graph traversal and source-specific trust weighting. Export a resolved identity graph.
**Must not require:** database concepts, embeddings, graph theory, fuzzy matching, legal entity terminology.
**Why software:** comparison across many records/relationships is materially stronger than a checklist.
**Saveable output:** verified/contested identity map with confidence and evidence.
**B-Web:** interactive identity graph where twelve labels collapse or refuse to collapse as the visitor inspects evidence; draggable merge/split decisions recalculate confidence and downstream relationships.
**B technology ceiling:** force-directed SVG/Canvas graph, provenance inspection, animated merge/split topology, accessible list/table equivalent.
**B-LinkedIn:** one apparent entity multiplies into conflicting records, then resolves into verified/ambiguous clusters.
**Infrastructure created:** entity registry, confidence model, relationship-edge schema, adjudication pattern, graph viewer.
**Verdict:** KEEP, but public framing must be concrete rather than “entity resolution.”

**B-LinkedIn:** “same AI, different consequence” transformation.
**Infrastructure:** consequence ontology, control mapping engine, policy-overlay interface.
**Verdict:** KEEP only with consequence-first public language; avoid generic risk-matrix product.
