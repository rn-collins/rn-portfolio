# Final Build Admission Scorecard

Status: REQUIRED BEFORE CANON FREEZE

Each proposed numbered build must pass all four gates below. A technically interesting idea that fails a public/product gate moves to RN Lab infrastructure or backlog rather than consuming a public accession.

## Gate 1 — Public strategic value (45 points)
Score 1–5 each:
1. RN fit
2. audience demand / problem relevance
3. saveability
4. visual-build potential
5. utility / adoption potential
6. technical progression
7. distinctiveness
8. click-through potential
9. commercial gravity

Guidance:
- 40–45 anchor build
- 34–39 strong candidate
- 29–33 reframe/replacement presumption
- <=28 remove from public canon unless materially reconceived

## Gate 2 — Product worthiness
PASS / REFRAME / FAIL for each:
- clear user and job-to-be-done;
- clear moment of use;
- first value quickly reachable;
- useful output/action, not information theater;
- software materially improves the outcome versus a PDF/checklist/article;
- technically ambitious only where ambition improves the result;
- no unnecessary account, integration, or expert setup on the primary path;
- uncertainty, evidence, assumptions and limits are intelligible;
- save/copy/export/share/revisit path where useful;
- privacy/security proportionate to the data and consequence;
- accessibility and mobile are product requirements;
- can plausibly produce a reason to contact RN after value is delivered.

## Gate 3 — Comprehension range
Test the SAME primary product against these QA lenses:
- younger / early-secondary reader with no domain knowledge;
- general adult with no specialist training;
- strong non-specialist reader;
- practitioner/professional in an adjacent field;
- domain professional;
- technical/domain expert.

These are internal QA lenses, not labels shown to visitors and not proxies for intelligence.

PASS only if:
- all six can identify the same core purpose, task and result;
- the first screen works without specialist vocabulary;
- concrete examples/actions appear before abstractions when possible;
- technical/legal/scientific terms are explained or progressively disclosed;
- instructions fit limited attention/working-memory contexts;
- expert rigor remains available in deeper layers, evidence and methodology;
- simplification does not change the meaning of consequential concepts;
- the interface does not infantilize general users.

Controlling rule: **general-public by default; expert depth on demand. One product, layered comprehension.**

## Gate 4 — A/B pair integrity
A must be a real functional system. B must be a bespoke visual communication build.

For A:
- user can complete the core job;
- output is defensible and actionable;
- implementation demonstrates genuine technical capability;
- later builds can inherit real infrastructure where appropriate.

For B:
- proposition/tension is clear;
- medium is chosen because it is best for the idea, not because the series requires one format;
- works silently;
- pacing permits comprehension without dead air;
- motion/interaction communicates meaning;
- contains an intellectual souvenir when warranted;
- LinkedIn-native derivative is specified;
- B reveals the problem A solves rather than functioning as a conventional ad.

## Required audit record per build
Before sequencing is frozen, each build record must state:
- public title;
- plain-language one-sentence job;
- target user(s);
- concrete use moment;
- novice/general-public path;
- professional/expert depth;
- maximum warranted technical architecture;
- what the visitor never needs to understand technically;
- public-value score;
- Gate 2 verdict;
- comprehension-range verdict;
- A concept;
- B concept;
- saveable payload;
- likely conversion path;
- infrastructure inherited;
- infrastructure created;
- dependencies/prerequisites;
- duplicate/boundary risks;
- final verdict: KEEP / REFRAME / REPLACE / LAB ONLY.

## Canon freeze condition
The final number and order are not canonical until every slot has an audit record and dependency-aware resequencing confirms there is no missing prerequisite capability between adjacent builds.
