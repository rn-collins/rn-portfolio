# RN Builds — 100 Builds Strategic Value Audit

**Status:** Pre-002 release gate  
**Purpose:** Re-audit the canonical 100 not only for engineering completeness, but for whether each cycle deserves scarce public attention and advances RN's body of work.

## Funnel objective

Every public cycle should be designed around:

> STOP → UNDERSTAND → SAVE → CLICK → USE → REMEMBER RN → CONTACT

The numbered canon is not a generic software curriculum. Lab infrastructure may teach or implement necessary technical capabilities without consuming a public numbered slot unless the public artifact itself passes the strategic-value test.

## Nine-factor score (0–5 each; 45 maximum)

1. **RN fit** — Does the problem credibly connect to RN's lived/professional fields, experiences, inquiries, sectors, or future direction?
2. **Audience demand** — Does a recognizable audience experience this problem often enough to care?
3. **Saveability** — Does B contain a framework, model, distinction, map, checklist, reference, or other intellectual souvenir worth revisiting?
4. **Visual potential** — Can B make the underlying mechanism visible rather than merely decorate an announcement?
5. **Utility / adoption** — Can A deliver useful value with a clear use case, low enough activation energy, understandable inputs, and an actionable output?
6. **Technical progression** — Does the cycle add or deepen a real capability that later builds can inherit?
7. **Distinctiveness** — Is the proposition differentiated from generic templates, commodity AI wrappers, and common thought-leadership content?
8. **Click potential** — Does B create a legitimate reason to continue to A rather than giving away or withholding the wrong amount?
9. **Commercial gravity** — Could the right viewer reasonably infer a relevant capability and want RN's help, collaboration, research, implementation, speaking, or advisory work?

### Disposition thresholds

- **39–45 — Anchor:** protect the slot; candidate flagship.
- **34–38 — Strong:** retain; refine positioning or execution.
- **29–33 — Conditional:** redesign, rename, combine with an RN-specific use case, or replace.
- **≤28 — Remove from public canon:** move to Lab infrastructure/backlog unless a materially stronger public expression is found.

No build survives merely because later software technically needs its capability.

## Mandatory gates beyond score

Every retained cycle must also pass:

- **A clarity gate:** a first-time visitor can identify who it is for, when to use it, what to provide, and what they receive.
- **A accuracy gate:** factual/legal/scientific claims are source-grounded; limitations are explicit; scoring is not disguised as certification.
- **A adoption gate:** useful first value is achievable without an account, sales call, lengthy onboarding, or unnecessary data collection unless the use case truly requires it.
- **B silent-feed gate:** the story works without audio.
- **B pacing gate:** every beat is readable before transition, but persistent/anticipatory motion prevents false endings.
- **B save gate:** the viewer leaves with at least one screenshot/pause-worthy intellectual payload.
- **A↔B integrity gate:** B reveals the actual problem A solves and does not overclaim A.
- **Conversion gate:** the build page offers a contextually relevant path to related work/contact without turning the artifact into a lead-gen trap.

## Public canon vs Lab infrastructure

A capability can be technically necessary and still fail the public-canon test. Authentication, deployment, generic API gateways, and similar primitives should remain unnumbered RN Lab infrastructure unless their public expression is reframed around a consequential RN-relevant question and independently earns its slot.

This is the principal issue the original completeness audit did not answer: **dependency completeness is necessary, not sufficient.**

### 001-A product finding

**Worthy of public use, but not yet final.** The current v1 is directionally strong and source-aligned, but a release-quality version should reduce user effort and increase actionability.

#### What already works

- no login;
- no backend submission of entered workflow information in the prototype;
- clear use case: inspect/design a human-review checkpoint in an AI-assisted workflow;
- explicit consequence context;
- reviewer competence, timing/trigger, review standard, evidence, authority, failure/escalation, recordkeeping, and anti-rubber-stamp conditions;
- gap detection rather than a cosmetic summary;
- clear statement that the output is not legal/compliance certification.

#### Required 001-A v1.0 improvements before public launch

1. Add a **60-second Quick Check** mode using mostly structured choices.
2. Keep the existing **Design the Control** mode for deeper work.
3. Replace the bare 0–8 score with a dimension view so users see *why* the architecture is weak/partial/strong.
4. Add contextual examples for legal work, HR, healthcare-adjacent, research, customer support, and general business workflows without implying universal legal requirements.
5. Produce a prioritized **Next 3 fixes** section rather than only listing every gap.
6. Add a copy/export function for the generated review protocol.
7. Make consequence level alter recommendations/urgency rather than merely appear in the output.
8. Add an explicit question about reviewer workload/time/resources, because nominal authority without practical capacity can make review ineffective.
9. Add a question about AI-system limitations/interpretability information available to the reviewer.
10. Add a lightweight 'test the control' prompt: sample review, override tracking, error/complaint review, and periodic reassessment.

### 001-B motion finding

The B artifact should be authored as a **continuous 4:5 silent motion composition**, not five static screens with automatic pagination.

#### Pacing standard

- The viewer must have enough time to fully read/comprehend a beat.
- The next motion should begin roughly **0.3–0.7 seconds before cognitive completion** of the current beat, so the viewer senses continuation.
- Dense text should never compete with complex motion.
- Simple dramatic phrases can hold ~1.5–2.0s; moderate reading beats ~2.2–2.8s; a saveable framework ~3–4s; the final CTA/build identity ~2.5–3.5s.
- The final hold is deliberately longer than intermediate holds to teach the viewer that the piece is actually finished.

#### Save payload for 001-B

The penultimate/final intellectual frame should resolve into:

**MEANINGFUL HUMAN REVIEW**

`TRIGGER → EVIDENCE → QUALIFIED REVIEW → DECISION`

with supporting controls:

`COMPETENCE · TIME · AUTHORITY · OVERRIDE · ESCALATION · RECORD · TEST`

The viewer should receive value even if they never click. The following build reveal then offers the deeper diagnostic tool.
