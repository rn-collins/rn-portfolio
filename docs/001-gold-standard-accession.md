# 001 Gold-Standard Accession

001 is the reference implementation for every later public build. Future accessions may differ in medium, domain, technical architecture and visual language, but they must meet the same quality logic.

## Visitor experience
1. Understand what the build is within seconds.
2. Know whether it is relevant without specialist background.
3. Reach first useful value quickly.
4. Receive an actionable result, not a score without meaning.
5. Access deeper evidence/methodology only when wanted.
6. Save/copy/export/share something useful when appropriate.
7. Understand limitations and uncertainty.
8. Encounter a contextual—not intrusive—route to working with RN.

## Comprehension
Primary path must work for a general audience. Test the same core product against younger/early-secondary, general-adult, strong non-specialist, adjacent-professional, domain-professional and expert lenses. All should reach the same core meaning. Expert precision belongs in progressive depth.

## Technical standard
Use the strongest technology that materially improves the result. Do not expose technical complexity as user homework. A sophisticated implementation with an obvious interface is preferred to a technically impressive interface that makes the user learn the machinery.

## Public accession anatomy
VIEW → USE A → WATCH/EXPLORE B → WHY → MAKING → METHOD → EVIDENCE → LINEAGE → VERSIONS → PRACTICE.

## Private lab anatomy
Acceptance gates, unresolved bugs, test fixtures, deployment operations, internal production instructions, analytics hypotheses, commercial hypotheses, research queues and backlog remain internal unless translated into a useful public lesson.

## B-side standard
The Visual Build must make the idea visible, work silently, pace for comprehension, use motion/interaction meaningfully, produce a saveable intellectual souvenir when warranted, and specify the LinkedIn-native derivative. It is not an advertisement slide deck.

## Release rule
001 does not become v1.0 merely because it deploys. Release requires product, comprehension, accessibility, evidence, QA, B-motion, public-record and conversion gates to pass in the live interface.
