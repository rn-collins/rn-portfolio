# Public Language Standard

Status: NON-NEGOTIABLE PROJECT LAW

## Core rule
The comprehension standard applies to **every public word**, not only instructions inside A-side tools.

That includes:
- homepage copy;
- navigation and room names;
- build titles;
- build subtitles;
- section headings;
- buttons and controls;
- form questions and answer choices;
- result labels;
- error and empty states;
- B-Web scene copy and interaction labels;
- B-LinkedIn on-screen copy;
- Behind the Build, Method, Evidence, Lineage, Versions, and Practice copy;
- technical capability descriptions when shown publicly.

## Controlling formulation
**General-public language first. Precise expert language available when it earns its place.**

A visitor should never need a degree, professional credential, technical background, or prior knowledge of RN's work to understand what a build is called, why it exists, or what to do first.

## Titles
A build title fails if a first-time general visitor cannot form a reasonably accurate guess about the build from the title plus one short plain-language subtitle.

Prefer titles that name:
- the question;
- the decision;
- the thing being made visible;
- the action the user can take;
- or the everyday problem being solved.

Do not lead with architecture jargon merely because the implementation is technically sophisticated.

Examples:
- "Multi-Agent Organization Designer" → "Design an AI Team"
- "Island Systems Dependency Mapper" → "What Does This Island Depend On?"
- "Governance Experience Assessment Tool" → "What Does This Rule Feel Like in Real Life?"
- "Neuroaesthetic Evidence & Decision-Support System" → "How Is This Space Affecting You?"

The technical/domain name may appear secondarily under "For professionals" / methodology / architecture / metadata if useful.

## Layering precision
Plain language must not erase important distinctions. Use this order:
1. concrete public phrase;
2. one-sentence explanation;
3. optional exact professional term;
4. deeper evidence/methodology.

## Failure conditions
Public copy fails if:
- a normal visitor must Google the title;
- nouns are stacked into an abstract technical phrase;
- the copy explains the implementation before the human problem;
- specialist acronyms appear before explanation;
- simplified wording materially changes the claim;
- a technically precise label is kept only because the team is accustomed to it;
- the B-side requires professional vocabulary to understand the visual argument;
- the visitor is made to feel the product is "not for people like me."

## QA question
Before release, ask a person unfamiliar with the field:
**From the title and first screen alone, what do you think this lets you do?**
If their answer is materially wrong or they cannot answer, rewrite it.
