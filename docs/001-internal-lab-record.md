# Build 001 — Internal Lab Record

Visibility: INTERNAL / NOT PUBLIC COPY

This file contains production material for the team building and auditing 001. Public visitors should receive translated lessons through the accession's Making / Method / Evidence pages, not raw operational notes.

## Internal-only material
- acceptance-gate status
- unresolved scoring questions
- browser QA defects
- deployment / preview instructions
- exact LinkedIn capture and export settings
- conversion hypotheses and analytics events
- internal commercial assumptions
- backlog and future-version candidates
- test fixtures and scenario expected outcomes
- source-verification queue
- performance budgets
- implementation details that do not help a visitor understand or reuse the method

## Translation rule
Before any internal note becomes public, ask:
1. Does this teach a reusable lesson, reveal a meaningful design decision, or help someone understand the evidence/limitations?
2. Can it be rewritten for a visitor rather than addressed to the production team?
3. Does publishing it create unnecessary security, privacy, operational, or commercial risk?
4. Is it useful enough to deserve attention?

If yes, publish the translated lesson in Making, Method, Evidence, Versions, or Lineage. If no, keep it here or in issues/tests/architecture records.
