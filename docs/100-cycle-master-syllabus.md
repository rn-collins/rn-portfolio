# RN Builds × LinkedIn Visual Builds
## Canonical 100-Cycle Master Syllabus

**Program promise:** 100 functional builds + 100 paired visual builds = 200 primary public artifacts.

**Sequence rule:** every later build must inherit capabilities created earlier. No build may quietly rely on an unrepresented lower-order capability. New numbered builds may be added after launch only when they exceed the capability ceiling established by Build 100.

## Universal module contract

Every cycle contains:

- **###-A Functional Build:** a working public artifact, not merely a concept document.
- **###-B Visual Build:** a bespoke LinkedIn-native visual, motion, reveal, or interactive composition that interprets and announces A.
- **Required record:** observation, missing system, intended users, inputs, logic, outputs, evidence requirements, limitations, inherited infrastructure, newly created infrastructure, tests, accessibility review, launch post, version, and later dependents.
- **Minimum completion standard:** usable MVP; mobile and desktop QA; documented lineage; no unsupported factual or legal claims; clear limitations; analytics event coverage; public build page; paired visual; launch copy.

## Program-level infrastructure outside the numbered 100

The following are required but are not separate public intellectual builds: RN design system, code conventions, registry and syllabus schema, reusable build-page template, CI checks, preview deployment workflow, analytics plumbing, asset pipeline, visual animation primitives, documentation generator, issue templates, dependency-map renderer, and exhibition search/filter components. They should be credited in lineage but must not inflate the numbered program.

## Freeze rule

The title and position of a build may change during pre-launch syllabus review only when dependency analysis justifies it. Once the public sequence launches, any newly proposed build must be classified as one of the following:

1. a feature of an existing build;
2. shared laboratory infrastructure;
3. a replacement for a demonstrably weaker build before that build launches;
4. a post-100 build that exceeds Build 100’s capability and complexity ceiling.

A missing foundational or intermediate capability discovered after launch is a syllabus defect, not an acceptable new insertion.
