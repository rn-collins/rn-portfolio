## On-screen transcript / storyboard

1. **A use case is not an implementation plan.** A promising capability can still outrun the organization expected to operate it.
2. **Start with who can be affected.** Severity, rights, reversibility, scale, and uncertainty determine how much readiness is required.
3. **Trace the real work.** Map intake, data, model, review, decision, action, monitoring, and every accountable handoff.
4. **Test the vendor claims.** A procurement adjective is not proof. Keep claim, scope, evidence, control, contract, and recourse inspectable.
5. **Owner · authority · skill · time · exit.** A control exists only when named people can run it, stop the use, correct failure, and sustain the work.
6. **Desire to deploy is not readiness.** Readiness is the ability to operate the controls—not the desire to deploy.
