# 100-wide interim findings

Across all three audit batches, the problem is now clearer:

## 1. The public canon is stronger than the original technical curriculum
Most later domain-specific builds are worth protecting.

## 2. Generic infrastructure consumes too many early slots
At minimum, the following should be removed from the numbered canon unless substantially reframed:

- Identity & Authentication Layer
- Data Ingestion & Connector Framework
- API Gateway & Integration Layer
- Deployment, Reliability & Observability System

Several others need stronger public expressions rather than deletion:

- Workflow State Machine
- Notification / Alerting
- Product Analytics
- Automated Testing
- Security / Threat Modeling
- generic schema/entity-resolution work

These should still exist as **RN Lab Infrastructure** and can later be shown inside more meaningful public products.

## 3. The freed slots should increase RN-specific coverage
Replacement competition should prioritize underrepresented but strategically important territories:

- AI procurement/vendor-claim verification
- policy-to-workflow implementation
- claim/evidence defensibility
- institutional friction and invisible work
- place-sensitive technology readiness
- human-state/neurotechnology claims
- physical space / third-space intelligence
- creator/Institutions-of-One ownership and autonomy
- technology history / hidden infrastructure where a real tool can exist
- IP/brand/knowledge-ownership systems

## 4. Several adjacent late builds need boundary tests, not removal
The regulatory intelligence cluster 069–079 and operating-system cluster 087–094 are strategically strong, but each must prove a distinct user, decision, input/output boundary and visual thesis.

## 5. Build order must be recalculated only after replacements are selected
Do not renumber yet. First score all replacement candidates against the weakest surviving builds. Then reconstruct the dependency sequence.

4. a B-side visual mechanism with a saveable intellectual souvenir;
5. evidence of RN fit;
6. a credible path from LinkedIn → use → contact;
7. technical capability contribution;
8. non-duplication with the remaining canon.
