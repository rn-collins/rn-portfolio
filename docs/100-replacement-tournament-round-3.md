# 100 Builds Replacement Tournament — Round 3

## Purpose
Round 3 begins exact incumbent-versus-challenger replacement decisions. It does not yet renumber the full sequence; it identifies which public slots no longer deserve generic infrastructure framing and which RN-specific public build should carry the underlying capability forward.

## Exact replacements — first locked set

### Former public slot: Identity & Authentication Layer
**Disposition:** move generic auth implementation to RN Lab infrastructure.
**Public replacement:** Creator Ownership Stack Mapper.
**Why this wins publicly:** preserves identity/dependency/permission thinking inside a much more consequential question: what does an independent operator actually own, control, rent, or risk losing? Strong Institutions-of-One fit, obvious saveable visual, and direct commercial relevance.
**Underlying capability preserved:** identity, ownership classification, access/dependency relationships, graph modeling.

### Former public slot: Data Ingestion & Connector Framework
**Disposition:** move generic connectors/ingestion machinery to RN Lab infrastructure.
**Public replacement:** AI Vendor Claim / Procurement X-Ray.
**Why this wins publicly:** the ingestion layer now has a reason to exist: collect vendor evidence, claims, documents and implementation facts into a comparison system that legal/procurement/technology teams can actually use.
**Underlying capability preserved:** multi-source ingestion, normalization, evidence extraction, comparison.

### Former public slot: API Gateway & Integration Layer
**Disposition:** move generic API-gateway implementation to RN Lab infrastructure.
**Public replacement:** Policy-to-Workflow Translator.
**Why this wins publicly:** integration becomes operational transformation: prose rules are translated into actors, triggers, obligations, deadlines, evidence, approvals and handoffs. The build still requires structured interfaces between source text, parser, workflow schema and outputs.
**Underlying capability preserved:** interface contracts, structured transformation, workflow APIs/integration boundaries.

### Former public slot: Deployment / Reliability / Observability System
**Disposition:** move deployment/reliability primitives to RN Lab infrastructure.
**Public replacement:** AI Implementation Readiness X-Ray.
**Why this wins publicly:** reliability becomes one component of a broader implementation-readiness question that organizations recognize before they deploy AI. This exposes prerequisites across workflow, data, permissions, review, integration, security, adoption and measurement.
**Underlying capability preserved:** readiness telemetry, dependency state, operational checks, prioritized remediation.

## Additional challengers retained for weak-incumbent matches
The following remain in the tournament because they are too strong to discard merely because the four confirmed Lab demotions have now been filled:
- Evidence Strength & Claim Defensibility Mapper
- Institutional Friction Detector
- Neurotechnology Claim Audit
- Place-Sensitive Technology Readiness Tool
- Human Consequence Map for AI Workflows
- Third-Space / Future-of-Place Decision Lab

These must compete against conditional/reframe incumbents rather than expand the canon beyond 100.

## Canon rule after Round 3
A public build may use substantial Lab infrastructure without exposing that infrastructure as the public proposition. The public proposition must be the consequential problem; engineering primitives remain visible in the build log and lineage record.
