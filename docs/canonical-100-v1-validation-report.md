# What “frozen” means
Frozen means the numbered public syllabus, public jobs, A/B relationships, major technology ceilings, convergence decisions and dependency spine are the source of truth for implementation.

Frozen does **not** mean an individual build cannot improve during research/design/engineering. Every build is expected to improve up to its local technological ceiling. A numbered slot changes only through a formal canon-change process showing that the replacement is materially stronger and does not break downstream lineage.

# Per-build release gate remains mandatory
Before any A/B cycle becomes public v1.0 it must separately pass:
- real user utility and first-value test;
- general-public comprehension + expert depth;
- accessibility and responsive QA;
- evidence/provenance/uncertainty review appropriate to domain;
- privacy/security review appropriate to risk;
- maximum-warranted-technology review by product engineer + creative technologist;
- B-Web collision, keyboard, touch, reduced-motion and passive-comprehension QA;
- B-LinkedIn silent-first 4:5 pacing/readability/export QA;
- A/B intellectual-integrity check;
- lineage proof: inherited capability is actually reused where claimed;
- Behind the Build / Method / Evidence public-transparency record;
- internal Lab Record separated from visitor-facing copy.
